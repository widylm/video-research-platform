# Автоматическая передача из Fashion Radar в «Кадр»

PR добавляет журнал завершённых сборов, отправитель для Windows, закрытый по умолчанию маршрут приёма и адаптер записи в каталог «Кадра». SQL лежит в `supabase/review` вне каталога применяемых миграций. Для рабочего включения нужно отдельное согласование.

## Откуда берутся записи

Предоставленные `browser.mjs`, `instagram-browser.mjs`, `extract.mjs`, `instagram.mjs` и `search.mjs` показывают поля старых записей и фазы процесса. По Issue №13 `collector/server.mjs` сохраняет завершённое состояние в `.tmp/results.json`. Отправитель поддерживает два ожидаемых формата, объект состояния `{ phase, items }` и обёртку `{ state: { phase, items } }`. Формат, путь и момент записи в реально установленной версии предстоит подтвердить.

- Локальный модуль принимает завершённый результат с максимум 50 строками. В режиме `--completed` каждый сбор сначала сохраняется в отдельный файл журнала. Режим `--results` использует прежний опрос одного файла, пропускает незавершённые состояния и известные признаки отмены, а при первом запуске начинает наблюдение с текущей версии файла.
- В пакет идут канонический HTTPS-permalink, ID, доступное описание, автор, дата, счётчики и хэштеги. Число `0` сохраняется отдельно от `null`. Имя автора берётся из ссылки TikTok. Старый `title` используется как подпись при известном происхождении. Самостоятельное название и число комментариев в предоставленном формате отсутствуют. `views` старого Instagram не переносится, поскольку это поле могло означать число запусков. Публикации Instagram, для которых старый код предположил `/reel/` по адресу `/p/`, исключаются.
- Повторные записи внутри результата убираются по `(platform, externalId)`. Канонический адрес проверяется локально. Оригинальные файлы, сырые ответы платформ, cookies и профиль Chrome не входят в формат. Отправитель не открывает порт 4319 и не обращается к платформам.

`collector/server.mjs` отсутствовал среди файлов, доступных при подготовке PR. Для точного подключения нужен этот файл и, если сохранение вынесено отдельно, используемый им модуль записи результата. Для сверки формата достаточно обезличенного `.tmp/results.json` с исходными именами и типами полей и вымышленными значениями. Для встраивания статуса в интерфейс также нужен файл, который отображает состояние.

## Точка подключения локального сборщика

Для версии `collector/server.mjs` из Issue №15 используйте [готовый локальный установщик для Windows](../tools/fashion-radar-local-journal/README.md). Далее описан контракт интеграции для других версий сборщика.

После отдельного согласования разработчик Fashion Radar импортирует `recordFashionRadarCompletion` из `lib/fashion-radar/completion.ts` установленной копии «Кадра». В ветке успешного завершения вызов должен дождаться записи **до** перезаписи `.tmp/results.json` и показа статуса «завершено». Используйте ID и время исходного запуска при каждом повторе локального сохранения. Например, перед существующей записью результата:

```js
await recordFashionRadarCompletion({
  directory: approvedCompletionDirectory,
  collectionId: runId,
  completedAt: completedAtIso,
  state: completedState,
  platforms: approvedPlatforms,
});
```

Это пример вызова, имена переменных и место встраивания нужно сверить с `collector/server.mjs`. Для импорта TypeScript используйте Node.js 22.12+ с `--experimental-strip-types`. Обрабатывайте ошибку записи как несохранённый сбор и оставляйте результат доступным для повторной записи. Ведите журнал на локальном диске с поддержкой жёстких ссылок, например NTFS. Слот журнала создаётся без перезаписи существующей записи. Отправитель удаляет файл журнала только после сохранения пакета в очереди. Даже когда очередь из 16 пакетов заполнена, следующие сборы остаются в журнале. Для Windows содержимое записывается с принудительным сбросом данных файла, а публикация файла атомарна; Node.js не поддерживает `fsync` самого каталога на Windows.

## Как будет работать подключение

1. Администратор «Кадра» проверяет право передачи данных для каждой платформы и выдаёт активному участнику или администратору ключ устройства только для согласованных платформ. Для будущей регистрации предлагается одноразовая выдача `UUID.секрет`, где секрет — 32 криптографически случайных байта в Base64URL. Сервер хранит SHA-256 секрета, роль и активность сверяются заново через профиль при каждом запросе. Доступ можно отозвать или ограничить сроком независимо от входа в браузер.
2. Локальный процесс отправляет пакеты версии 1 только на согласованный HTTPS-маршрут `/api/integrations/fashion-radar` с ключом в заголовке Authorization. Перенаправления останавливают отправку. Очередь привязана к серверу и идентификатору устройства. Код устройства передаётся через защищённое окружение процесса. Он не используется в браузере и не даёт доступ к другим функциям «Кадра».
3. Приёмник проверяет ключ, срок действия, отзыв, активную роль и разрешение источника. Вход ограничен 512 КиБ и 1000 строками. Схема `bulkImportSchema` и проверка полей блокируют посторонние данные, несоответствующие URL, `mock:*` и повторы внутри входного пакета. База атомарно выдаёт до 10 запросов на устройство в минуту, включая невалидные пакеты после авторизации. Для доступа из интернета согласуйте входное ограничение на Cloudflare перед подключением базы к публичному маршруту.
4. Локальная очередь хранит до 16 пакетов и заменяет файл атомарно. При 429, 408, 5xx и сетевом сбое повтор откладывается с увеличением паузы, с учётом `Retry-After` до суток. При отказе в доступе, другом постоянном отказе или перенаправлении процесс останавливается с сохранением очереди. `Ctrl+C` прекращает работу. После подтверждённой доставки пакет удаляется из очереди.

Приём записи выключен без `KADR_FASHION_RADAR_ENABLED=1` и `KADR_FASHION_RADAR_DB_URL`. На первом этапе используется отдельное тестовое окружение. После согласования проверяющий базы применяет SQL из `supabase/review`, создаёт пароль только для ограниченной роли `kadr_radar_ingest` и включает для неё `LOGIN`. В `psql` безопаснее задать пароль через `\password kadr_radar_ingest`. Рабочие реквизиты в этой ветке не используются.

Для Worker передайте строку подключения через защищённый секрет Cloudflare. В строке Supavisor указывается `kadr_radar_ingest.<project-ref>` вместо `postgres.<project-ref>`. Используйте соединение с сертификатом, доверенным средой Worker. Адаптер требует TLS с проверкой сертификата и отклоняет параметры строки подключения, которые могли бы изменить TLS. Роль может вызвать только две функции импорта в закрытой схеме `private`, а прямых прав на карточки и хеши устройств у неё нет. Ключ `service_role` для этого маршрута не нужен. [Подключение PostgreSQL](https://supabase.com/docs/guides/database/connecting-to-postgres) · [Подключение из Workers](https://developers.cloudflare.com/workers/databases/connecting-to-databases/)

Администратор тестовой базы регистрирует устройство в `private.fashion_radar_devices` с ID профиля, хешем случайного секрета, разрешёнными платформами и `expires_at`. В локальный процесс передаётся `UUID.секрет`. Для отзыва администратор выставляет `revoked_at`. Отдельного экрана выдачи ключей в этом PR нет.

## Схема и повторная запись

`public.fashion_radar_snapshots` хранит последний известный снимок по `(platform, external_id, source)`. В той же транзакции создаётся обычная карточка в `public.videos`, доступная через существующий поиск, избранное и коллекции. Если карточка ранее заведена вручную, меняется только отдельный снимок. Для карточки, заведённой синхронизацией, новые снимки обновляют метрики, дату и хэштеги. Ручные название, описание и автор сохраняются. ID и ссылки избранного и коллекций сохраняются. RLS разрешает чтение снимков активным участникам команды.

Функция записи повторно проверяет отзыв, роль и разрешённые платформы в транзакции. Данные обновляются только при более свежем `fetched_at`. Равные и устаревшие записи считаются повторами. При потере ответа после фиксации транзакции повтор пакета возвращает число повторов без создания второй карточки. [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)

## Windows после одобрения пилота

После встраивания вызова понадобятся Node.js 22.12+, рабочая папка этого PR с установленными зависимостями, путь к каталогу журнала, HTTPS-адрес отдельного тестового приёмника и ключ устройства. До выдачи адреса и ключа проверяйте интеграцию командами тестов ниже.

В PowerShell из папки PR измените только значения путей и адреса, не исходный код. Выберите только платформы, для которых согласована передача. На Windows храните очередь в каталоге профиля пользователя, закрытом для других учётных записей.

```powershell
$completed = Join-Path $env:LOCALAPPDATA 'Kadr\Radar Sync\completed'
$queue = Join-Path $env:LOCALAPPDATA 'Kadr\Radar Sync\queue.json'
$endpoint = 'https://staging.example.org/api/integrations/fashion-radar'
$kadrKey = Read-Host 'Ключ устройства' -AsSecureString
try {
  $env:KADR_RADAR_DEVICE_TOKEN = [pscredential]::new('kadr', $kadrKey).GetNetworkCredential().Password
  npm run --silent sync:fashion-radar -- --enable --endpoint "$endpoint" --completed "$completed" --queue "$queue" --platforms tiktok,instagram
} finally {
  Remove-Item Env:\KADR_RADAR_DEVICE_TOKEN -ErrorAction SilentlyContinue
  $kadrKey.Dispose()
}
```

Запустите один процесс, дождитесь сообщения «Синхронизация ожидает завершённые результаты» и работайте с Fashion Radar как обычно. В терминале появляется «Передано N / отклонено M / повторов D». При переполнении очереди дождитесь доставки перед следующим сбором. Приём пакета с ещё не разрешённой платформой остановит процесс, даже если локально она была указана. После аварийного завершения запуск может потребовать удаления `queue.json.lock`. Делайте это только после проверки, что процесс действительно остановлен. Очередь `queue.json` оставьте для возобновления передачи. При отзыве разрешения остановите процесс и согласуйте удаление остатка очереди.

Режим `--results` остаётся совместимым с прежним запуском. Он читает один перезаписываемый файл каждые две секунды и может пропустить два быстрых сохранения. Для пилота передачи каждого запуска используйте `--completed`. Сначала проверьте два завершения подряд, отключение сети и последующий повтор, затем наличие обеих карточек в поиске и отзыв ключа.

## Условия передачи

- **TikTok.** Сначала подтвердите применимую региональную редакцию условий, разрешение на способ получения данных и право передавать и хранить поля в командном каталоге. Например, условия США требуют письменного разрешения для автоматизированного извлечения. Developer Terms допускают использование Developer Services по их документации и ограничениям. Публичный permalink сам по себе передачу и хранение не разрешает. [TikTok Terms of Service, США](https://t.tiktok.com/legal/page/us/terms-of-service/en) · [TikTok Developer Terms](https://t.tiktok.com/legal/page/global/tik-tok-developer-terms-of-service/en)
- **Instagram.** Meta требует предварительного разрешения для автоматизированного сбора. Для данных официального API согласованный сценарий должен включать хранение, доступ команды и удаление данных. App Review другого сценария или публичность ролика не подтверждают перенос из Chrome/CDP. [Позиция Meta по сбору](https://about.fb.com/news/2021/04/how-we-combat-scraping/) · [Meta Platform Terms](https://developers.facebook.com/terms/)

В предоставленном локальном коде есть обращения к внутренним данным площадок. Разрешения на такой сбор и последующую передачу пока не подтверждены. До проверки используйте только синтетические записи. Перед реальным пилотом отдельно подтвердите допустимый источник, объём обрабатываемых полей, срок хранения, доступ команды и порядок удаления для каждой платформы.

## Проверки

```bash
node --experimental-strip-types --test tests/e2e/fashion-radar-sync.test.mjs
node --experimental-strip-types --test tests/e2e/fashion-radar-schema.test.mjs
npm run check
npm run cf:build
npm run test:e2e
```

Тест схемы запускает временный PostgreSQL без сети и проверяет права. E2E использует синтетические результаты, локальный приёмник и отдельную PostgreSQL с TLS и проверяет появление карточек в существующем каталоге. Все SQL-файлы читаются для тестов только в одномоментных контейнерах Docker.
