# Подготовка метаданных к массовому импорту

`normalizeFashionRadarVideo(platform, record)` принимает одну заранее сохранённую запись по структуре `extract.mjs` или `instagram.mjs` Fashion Radar. Он возвращает объект `ProviderVideo` для `BulkSearchProvider.fetchPage` из PR №9. `searchBulk` добавляет `platform`, идентификатор поставщика `source` и время получения страницы `fetchedAt` в UTC. В текущем пилоте используются демонстрационные поставщики. Тестовые JSON-записи синтетические, по формам полей из приложенного кода.

- TikTok использует строковый ID, имя аккаунта из ссылки или записи, поля статистики и описание `desc`. `title` используется как отдельное название при наличии самостоятельного описания и при отличии от него. Явно переданные `originalTitle` и `video_title` также поддерживаются.
- Instagram использует публичный shortcode, имя аккаунта, подпись и доступные счётчики. `play_count` не подменяет просмотры. При скрытых просмотрах и лайках сохраняется `null`. Instagram-видео с неизвестным типом публикации может иметь ID и метаданные без ссылки. Адрес `/reel/` выводится из shortcode при явном признаке Reels или берётся из полной переданной ссылки. Поддержка массового пилота ограничена Instagram Reels.
- Ссылки проходят проверку HTTPS, платформы и соответствия ID. Параметры отслеживания отбрасываются. Короткие ссылки не раскрываются. Фото исключаются при наличии признаков фото, а неизвестные поля остаются `null`. Из подтверждённых счётчиков `0` сохраняется как число. Из текста извлекаются только явные хэштеги.
- `searchBulk` принимает необязательные `filters.publishedFrom` и `filters.publishedTo` как ISO-моменты с часовым поясом. Границы включительны. `minViews` и `minLikes` принимают целые неотрицательные значения. При заданном фильтре неизвестное значение не проходит этот фильтр. После фильтрации сохраняется первое подходящее видео на пару `(platform, externalId)`. Результаты учитываются в лимите после фильтрации и удаления дубликатов. Лимиты страниц и бюджета PR №9 действуют при любом числе совпадений.

## Формат будущего импорта в Supabase

`bulkImportSchema` проверяет JSON-пакет и возвращает только разрешённые поля. Пример с синтетическими данными предполагает будущий импорт после проверки источника и прав использования.

```json
{
  "version": 1,
  "videos": [
    {
      "platform": "instagram",
      "externalId": "Fixture_Reel-2",
      "url": "https://www.instagram.com/reel/Fixture_Reel-2/",
      "originalTitle": null,
      "originalDescription": "Без хэштегов",
      "author": "fixture.reels",
      "publishedAt": null,
      "views": null,
      "likes": null,
      "comments": 2,
      "hashtags": [],
      "source": "fixture:instagram",
      "fetchedAt": "2026-11-20T12:00:00.000Z"
    }
  ]
}
```

Пакет содержит от 1 до 1000 уникальных записей. Каждой нужна полная ссылка на видео с совпадающим ID. Дубликаты внутри пакета, данные из `mock:*` и ссылки на посторонние сайты отклоняются. Сырые ответы, медиафайлы, тексты комментариев, учётные данные и пользовательские заметки в пакет не входят. Успешная проверка формата сама по себе не подтверждает, что публикация доступна или что права на её данные получены.

Перед подключением записи в Supabase отдельно согласовать хранение снимков полученных метаданных. Текущая `videos` предназначена для каталога и не вмещает все поля пакета, в том числе счётчик комментариев и время получения. Снимок привязывать к видео по `(platform, external_id)`, при повторной загрузке обрабатывать совпадение на стороне базы и сохранять пользовательские заметки и редакции отдельно. В будущем сервер перед записью должен проверить активность участника, право импорта и доверенный источник, ограничить размер файла и выполнить запись с применением RLS. Проверки формата в этом PR локальные. [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)
