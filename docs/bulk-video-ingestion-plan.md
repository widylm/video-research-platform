# Массовый сбор 500–1000 видео для «Кадра»

Проверено по официальной документации 19 ноября 2026 года. Документ описывает будущую интеграцию. Доступ к API и фактическую выдачу ещё предстоит проверить на одобренных аккаунтах.

## Какой источник подключать первым

Для коммерческого исследования чужих роликов начать с **Instagram Business Discovery по списку известных профессиональных аккаунтов**. Этот сценарий даёт автоматическую подборку видео без ввода ссылок на каждый ролик. Дополнить его Instagram Hashtag Search, если Meta одобрит доступ и хватит выдачи по теме. Для TikTok первым подключать Display API для собственных аккаунтов и авторов, согласившихся на подключение. Если нужны сотни произвольных чужих TikTok-видео по теме, сначала нужен источник с правом коммерческого использования и хранения данных. [Instagram Business Discovery](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-facebook-login/business-discovery) · [Instagram Hashtag Search](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-facebook-login/hashtag-search) · [TikTok Display API](https://developers.tiktok.com/docs/en/display-api-overview)

## Разрешения, лимиты и расходы

- **TikTok Display.** Нужны одобренное приложение TikTok for Developers, Login Kit, `video.list` и согласие владельца каждого аккаунта. Для данных профиля запрашиваем только нужные разрешения. `video/list` и `video/query` принимают до 20 видео за вызов. Документированный стандартный лимит каждого из этих endpoints — 600 запросов за скользящую минуту. Для 500–1000 известных роликов один полный проход — минимум 25–50 страниц, если они заполнены. При многих аккаунтах страниц будет больше. Проверяем, что согласованный с TikTok сценарий разрешает хранение и обновление метаданных. [Подключение Display](https://developers.tiktok.com/docs/en/display-api-get-started/) · [Лимиты](https://developers.tiktok.com/docs/en/tiktok-api-v2-rate-limit) · [Условия ревью](https://developers.tiktok.com/docs/en/app-review-guidelines)
- **TikTok Research.** Доступ по заявке для подходящих исследователей и одобренной некоммерческой цели. Разрешение `research.data.basic`. До 100 роликов или комментариев на страницу. FAQ указывает общую квоту 1000 запросов в сутки. Для видео это минимум 5–10 заполненных страниц. Новые видео могут появляться с задержкой до 48 часов, счётчики — обновляться до 10 дней. Перед хранением любых результатов нужно проверить условия проекта и разрешения на экспорт, особенно если доступ идёт через защищённую VCE. [Правила доступа](https://developers.tiktok.com/products/research-api/) · [Квоты и задержки](https://developers.tiktok.com/docs/en/research-api-faq/) · [VCE и экспорт](https://developers.tiktok.com/docs/en/vce-getting-started)
- **Meta.** Для подключаемых Business/Creator-аккаунтов нужны Meta App, соответствующий вход и разрешения на чтение медиа. Для Insights требуется разрешение на статистику. Для клиентов вне ролей приложения — Advanced Access после App Review и Live mode. Для Business Discovery документация Facebook Login указывает `instagram_basic`, `instagram_manage_insights`, `pages_read_engagement` и привязку к Facebook Page. Для Hashtag Search Meta указывает App Review, `instagram_basic` и Instagram Public Content Access. Поддерживаются Facebook Login и подходящий Unified Login. Следуем требованиям выбранного режима и проверяем выдачу в одобренном приложении. [Business Discovery — разрешения](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user/business_discovery) · [Hashtag Search — требования](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-facebook-login/hashtag-search) · [Unified Login — доступ](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/eligibility-and-troubleshooting)
- **Квоты Meta.** Hashtag Search позволяет использовать 30 уникальных хэштегов на профессиональный аккаунт за скользящие 7 дней, до 50 объектов на страницу. 500–1000 роликов — минимум 10–20 полностью заполненных страниц только с видео. Реально нужны дополнительные страницы из-за фото, дублей и фильтров. С 16 февраля 2027 года Meta объявила предел 200 результатов на один запрос `top_media`. Hashtag Search и Business Discovery также подчиняются платформенным ограничениям Graph API. За квотой следим по заголовкам использования и ошибкам Graph API. Для User token Meta не публикует точное число вызовов, поэтому фиксированную скорость не обещаем. [Лимиты Graph API](https://developers.facebook.com/docs/graph-api/overview/rate-limiting/) · [Изменения top_media](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-facebook-login/hashtag-search#top-media-changes)
- **Бюджет.** В проверенных руководствах Display API и Instagram Graph API нет публичного тарифа за вызов. Это позволяет планировать пилот без покупки API после одобрения доступа. Доступ TikTok for Business и любые партнёрские условия уточняем отдельно. Для инфраструктуры проверяем CPU и число подзапросов Workers Free, а в Supabase Free учитываем 500 МБ базы и 5 ГБ исходящего трафика в месяц без кэша. Главные переменные расходы — частота обновления и объём истории и комментариев. Результаты пилота решат, помещается ли регулярный запуск в бесплатные квоты. [Workers Pricing](https://developers.cloudflare.com/workers/platform/pricing/) · [Workers Limits](https://developers.cloudflare.com/workers/platform/limits/) · [Supabase Pricing](https://supabase.com/pricing)

Для 500–1000 видео даже одна страница комментариев на видео даст 500–1000 запросов, без учёта ответов, повторов и метаданных. Например, при 250 верхнеуровневых комментариях на каждом ролике и размере страницы 100 потребуется 1500–3000 вызовов даже без ответов. При квоте TikTok Research 1000 в сутки такой проход займёт минимум два–три дня, если квота доступна целиком. Пропускать видео можно по подтверждённому нулю. При отсутствии счётчика объём комментариев остаётся неизвестным.

Первый пилот соберёт только счётчики. Если нужен анализ текстов и есть право на сбор, начать с отдельной выборки 50 роликов и до 20 верхнеуровневых комментариев на ролик. Хранить счётчик платформы, число фактически полученных строк, наличие следующей страницы и статус покрытия отдельно. При переходе на 500–1000 видео такой потолок даст до 10–20 тыс. строк. При условных 0,5–1 КиБ на запись это порядка 5–20 МиБ исходных данных, без индексов и истории. Срок хранения, права чтения и удаление по правилам платформ согласовать отдельно. Сохранять тексты только у разрешённых источников, а идентификаторы авторов комментариев — только если нужны предмету исследования.

## Пакетный сбор и обновление

Интерфейс «Кадра» создаёт задание и показывает прогресс. Postgres в Supabase хранит очередь и контрольные точки, а серверный обработчик в Cloudflare Worker забирает готовые задания по расписанию. Сначала несколько страниц за запуск. Размер шага выбираем на пилоте по времени CPU и числу подзапросов. Секреты храним на сервере, права на постановку заданий и чтение результатов связываем с существующими ролями команды. [Cloudflare Cron Triggers](https://developers.cloudflare.com/workers/configuration/cron-triggers/) · [Workers Limits](https://developers.cloudflare.com/workers/platform/limits/)

1. **Задание.** Участник выбирает источник, подключённые или известные аккаунты, хэштеги, окно дат, слова, ограничения и количество уникальных видео. В первой итерации разрешённые источники ограничены явным списком. Ролики добавляются из страниц API или разрешённого файла, отдельные ссылки вводить не требуется.
2. **Обработка на сервере.** Один адаптер на источник возвращает страницу, курсор, признаки доступности полей и время ответа. Задание хранит ссылку на подключение, курсор и прогресс, но не токен в открытых полях. Один запуск обрабатывает ограниченное число страниц в пределах квот. Успешная запись пакета и контрольной точки выполняются вместе. Короткие повторы с паузой и разбросом для HTTP 429/5xx, с учётом `Retry-After` и кодов платформы. При проблеме прав или отзыве OAuth задание приостанавливается до повторного подключения. Ссылки пагинации обрабатываются на сервере и проверяются по официальному хосту, параметры с токенами исключаются из логов.
3. **Дедупликация.** Сохраняем существующий ключ каталога по платформе и каноническому ID. TikTok `int64` читаем без округления и храним строкой. У Instagram отдельно записываем ID Graph API и shortcode из канонического permalink. Это позволяет объединять результаты Hashtag Search, Business Discovery и ранее сохранённые ссылки. Повторный запуск обновляет источник и статистику без дублей. Существующие ID карточек, избранное и связи коллекций остаются основой каталога.
4. **Раздельные данные.** Слой оригиналов хранит `original_title`, `original_caption`, `account_username`, `published_at`, `permalink` и `source_hashtags`, а также источник, время получения и статус. Слой команды хранит редактируемые `team_title` и `team_notes`. Импорт пишет только оригиналы и метрики. В интерфейсе приоритет у названия команды, затем у оригинального названия, затем у первой строки оригинальной подписи. Если платформа не отдаёт отдельное название, `original_title` остаётся `NULL`. Хэштеги из подписи помечаем как извлечённые из текста. Явно полученный пустой список отличается от отсутствующего поля. Существующие ручные названия и описания при будущей миграции переносим в поля команды, а оригиналы заполняем только подтверждёнными данными.
5. **Статистика.** Храним доступные просмотры, лайки и число комментариев с источником метрики, охватом и `observed_at`. При успешном ответе без поля сохраняем `NULL` и причину, если она известна. Ноль записываем только при явном нуле в ответе. При временной ошибке отмечаем устаревание снимка. Обновление начинаем раз в сутки для активных подборок и реже для старых, ориентируясь на квоты. Для Display используем запрос до 20 ID за раз, для Discovery обновляем известные аккаунты, а для Hashtag Search регулярно собираем 24-часовое окно и учитываем, что обновить старые чужие ролики этим способом нельзя. Оригиналы видео и обложки не загружаем. Плеер открывается по кнопке из разрешённой ссылки.
6. **Проверка перед запуском.** После согласования запустить пилот на 50–100 видео, сравнить доступность каждого поля с несколькими публикациями, проверить сохранение курсора после сбоя, отсутствие дублей и сохранность заметок после обновления. Замерить расход квоты, объём хранения и долю подходящих видео. Затем увеличить цель до 500, потом до 1000. При исчерпании источника или квоты интерфейс показывает фактическое число уникальных результатов и причину остановки. Текущий поиск каталога ограничен 100 результатами за запрос, поэтому для исследования большой подборки отдельно предусмотрим серверную пагинацию и стабильную сортировку. При заданном пороге по метрике строка с `NULL` не считается совпадением.

## Что не покрывает бесплатный коммерческий сценарий

- Свободный глобальный поиск чужих органических роликов TikTok по словам, хэштегам и архивным датам. TikTok Research обладает нужными средствами поиска, но требует некоммерческого исследовательского допуска. Commercial Content API полезен, только если вопрос касается рекламы или раскрытого коммерческого контента. [TikTok Research Tools](https://developers.tiktok.com/products/research-api/) · [Commercial Content API](https://developers.tiktok.com/products/commercial-content-api)
- Полный поиск всех Instagram Reels по произвольному тексту, любому историческому интервалу и всем личным аккаунтам. Hashtag Search даёт ограниченную выборку, Business Discovery требует заранее известного профессионального аккаунта. Просмотры из Hashtag Search и тексты комментариев чужих публикаций в стандартном API недоступны. [Hashtag Search](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-facebook-login/hashtag-search) · [Business Discovery](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-facebook-login/business-discovery)
- Гарантия 500–1000 релевантных уникальных роликов за один запуск и одинаковый набор полей для каждого результата. Просмотры Instagram Business Discovery и TikTok также имеют разные определения. Сравнение метрик учитывает источник, а отсутствие значения показывается как «Нет данных».

## Законные альтернативы

- **Согласившиеся авторы и их выгрузки.** Подключение OAuth даёт автоматическую выборку из разрешённых аккаунтов. Для исторических данных возможен пакетный импорт официальной выгрузки или отчёта правообладателя. Покрытие ограничено участниками, а в файле могут отсутствовать метрики, тексты комментариев или permalink. Разовый файл не обновляет статистику сам. Импорт разрешённых CSV/JSON можно добавить после согласования формата. [TikTok Display API](https://developers.tiktok.com/docs/en/display-api-overview) · [Instagram Unified Login](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login)
- **TikTok Data Portability и Content Suite.** Data Portability позволяет получить разрешённые данные пользователя из ЕЭЗ или Великобритании после одобрения и его согласия. Проверяем фактические поля архива. Content Suite подходит рекламодателям для подбора роликов, связанных с брендом. Если доступная выгрузка разрешает использование в «Кадре», её можно принять отдельным пакетом. Покрытие и экспорт ограничены выбранным продуктом. [Data Portability](https://developers.tiktok.com/products/data-portability-api/) · [TikTok Content Suite](https://ads.tiktok.com/resources/help/article/about-tiktok-content-suite)
- **Лицензированный набор или партнёрский API.** Если нужны произвольные чужие ролики TikTok, запрашиваем письменное подтверждение источника данных, права коммерческого использования, хранения и обновления, покрытие по платформам и цене. Проверяем пробную выборку до покупки. Фиксированной цены для такого объёма нет без договора и условий поставщика. Сервисы с обходом авторизации, капч и ограничений в план не входят.
- **Одобренное некоммерческое исследование.** TikTok Research Tools и Meta Content Library могут дать более широкую выборку, если проект соответствует правилам. Это отдельный сценарий с проверкой допуска и разрешённого экспорта, включая данные комментариев. [TikTok Research Tools](https://developers.tiktok.com/products/research-api/) · [Meta Content Library — допуск](https://developers.facebook.com/docs/content-library-and-api/get-access/)
