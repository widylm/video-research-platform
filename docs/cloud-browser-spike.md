# Облачный исполнитель «Кадра»

Issue №18. В отдельной конфигурации «Кадра» раздел «Массовый поиск» запускает поиск по нейтральному HTML-документу. Результаты видны в отдельном тестовом каталоге. Исполнитель принимает только фиксированный разрешённый источник, выделенный в конфигурации сервера. Запрос пользователя применяется к тексту страницы и не меняет адрес, который открывает браузер.

## Маршрут запроса

1. Интерфейс отправляет запрос по контракту `BulkQuery` на `/api/cloud-browser`. Маршрут сверяет происхождение запроса и текущий профиль Supabase. Активные участники и администраторы могут запускать задания. Идентификатор профиля выставляет сервер.
2. Next.js вызывает отдельный Worker через приватный service binding. Durable Object переводит задачу через `pending`, `running`, `completed` или `failed`. Один общий слот и транзакционная квота предотвращают параллельные запуски. Состояние и ошибки видны в браузере. При перезагрузке раздел снова получает последнее задание текущего участника.
3. Исполнитель вызывает `@cloudflare/puppeteer` через binding `BROWSER`. Адаптер источника отдельно читает страницу и нормализует метаданные. Браузер не загружает сторонние ресурсы и не переходит по ссылкам с тестовой страницы. Локальный режим принимает только `http://127.0.0.1:<порт>/catalog`. Для облачной проверки оператор указывает один точный HTTPS-адрес `/catalog` на подконтрольном ему `pages.dev` или `workers.dev`.
4. Проверенные поля записываются в тестовое SQLite-хранилище Durable Object по каноническому URL. Обновление наблюдения сохраняет отдельные ручные поля и отбрасывает устаревшие снимки. Для будущих адаптеров интерфейс поддерживает выход `BulkVideo`. Текущий документ имеет свой тип и не появляется в каталоге видео, избранном или коллекциях.

Запуск и чтение ограничены таймаутом. Исполнитель закрывает сессию в `finally`, а при запоздалом завершении запуска планирует закрытие в фоне. У самой сессии задано 30 секунд простоя. Контрольное событие Durable Object снимает занятый слот после прерывания, без повторного запуска. 429 от Browser Run, отказ источника и таймаут дают отдельные причины. CAPTCHA или аналогичная ручная проверка помечается `manual_intervention_required`. Исполнитель останавливается. Возможность пройти проверку человеком отдельно не подтверждает права на дальнейший автоматизированный сбор.

## Локальная проверка и CI

```bash
npm ci
npm run check
npm run cf:build
npx playwright install --with-deps chromium
npm run test:cloud-browser
```

Команда запускает тесты лимитов и отказов, затем отдельный сценарий Playwright. Он поднимает изолированную базу входа и разрешённую loopback-страницу, использует авторизованный интерфейс «Кадра» и запускает Chromium на серверной стороне через локальную эмуляцию Browser Run в Wrangler. Wrangler при необходимости устанавливает Chromium для своего адаптера отдельно от браузера Playwright. Провайдерский аккаунт для этих тестов не используется. Тест проверяет доступ редактора, отказ анонимному посетителю и наблюдателю, занятый слот, извлечённый текст и блокировку побочных запросов. Нулевая выдача, таймаут, ограничение, CAPTCHA и идемпотентность проверяются изолированно. Обычный `npm run test:e2e` включает эти же тесты. [Локальный режим Wrangler](https://developers.cloudflare.com/browser-run/reference/wrangler/)

Для ручной проверки запустите локальный HTTP-источник в отдельном терминале.

```bash
node --input-type=module -e 'import { createServer } from "node:http"; createServer((req, res) => req.url === "/catalog" ? res.writeHead(200, { "Content-Type": "text/html; charset=utf-8" }).end("<h1>Catalogue of mosses</h1><p>Field notes.</p>") : res.writeHead(404).end()).listen(4100, "127.0.0.1")'
```

В корневом `.dev.vars` задайте `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY` своего тестового Supabase. В `workers/cloud-browser/.dev.vars` задайте `KADR_BROWSER_SOURCE=local` и `KADR_BROWSER_SOURCE_URL=http://127.0.0.1:4100/catalog`. После сборки запустите обе конфигурации. Войдите как активный участник или администратор, откройте «Массовый поиск» и отправьте запрос `mosses`.

```bash
npx wrangler dev --local -c wrangler.cloud-browser.jsonc -c workers/cloud-browser/wrangler.jsonc
```

## План отдельного облачного пилота

1. После согласования подтвердить тариф Workers Free и доступ к Browser Run на аккаунте. Подготовить подконтрольную команде публичную статическую HTML-страницу `/catalog` на `pages.dev` или `workers.dev`. Достаточно заголовка и абзаца из примера выше.
2. Создать закрытый Worker `kadr-cloud-browser-executor` по отдельной конфигурации. Для Durable Object предусмотрена декларация инициализации SQLite. Задать `KADR_BROWSER_SOURCE=hosted` и `KADR_BROWSER_SOURCE_URL` с точным адресом страницы. Миграции Supabase для этого шага не требуются.
3. Создать `kadr-cloud-browser-preview` на отдельном тестовом адресе. Настроить аутентификацию тестового Supabase и приватный service binding к исполнителю. Рабочий Worker использует прежний `wrangler.jsonc`.
4. Выполнить один поиск с ожидаемым словом страницы. Проверить результат в интерфейсе, метрики и закрытие сессии в Cloudflare. `wrangler dev --local` не подтверждает квоту, доступ и выполнение в аккаунте Cloudflare.

## Условия для TikTok и Instagram

- **TikTok.** Display API показывает публичные видео подключившихся авторов через OAuth `video.list`. Research API поддерживает ключевые слова и хэштеги, но доступ зависит от организации, региона и одобрения некоммерческого исследования. Commercial Content API покрывает соответствующую библиотеку коммерческого контента. Для общего каталога органических роликов нужно разрешение на источник, область поиска и хранение метаданных. Например, условия США требуют письменного разрешения на автоматизированное извлечение. [Display API](https://developers.tiktok.com/docs/en/tiktok-api-v2-video-list/) · [Research API](https://developers.tiktok.com/products/research-api/) · [Commercial Content API](https://developers.tiktok.com/products/commercial-content-api/) · [Условия США](https://t.tiktok.com/legal/page/us/terms-of-service/en)
- **Instagram.** Для ограниченного пилота по точному тегу подходит Hashtag Search с `Instagram Public Content Access`, `instagram_basic`, одобренным приложением и полномочиями на профессиональный аккаунт. `recent_media` покрывает последние 24 часа, до 50 публикаций на страницу и 30 разных тегов за скользящие 7 дней на аккаунт. Нет гарантии числа Reels, авторов и просмотров в этой выдаче. Для автоматизации страницы требуется предварительное разрешение Meta. [Hashtag Search](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-facebook-login/hashtag-search) · [Recent Media](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-hashtag/recent-media) · [Разрешения Meta](https://about.fb.com/news/2021/04/how-we-combat-scraping/)

Для цели в 500–1000 роликов нужно до запуска получить согласованный доступ или договор на подходящий индекс. В договоре должны быть подтверждены платформы и регионы, покрытие чужих органических публикаций, разрешённые поля, квоты пагинации, цена, срок хранения, доступ команды и удаление. Качество и полноту нужно измерить на небольшой разрешённой выборке. Рабочая запись видео потребует отдельного ревью адаптера и хранения происхождения, времени получения и метаданных с ключом `(platform, external_id)`. Права редакторов, ручные поля и связь карточек с коллекциями и избранным должны сохраниться. Секреты источника должны оставаться на сервере. [RLS Supabase](https://supabase.com/docs/guides/database/postgres/row-level-security)
