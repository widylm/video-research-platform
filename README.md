# Кадр

Русскоязычное рабочее пространство для команды из 2–5 человек, которая исследует короткие видео TikTok и Instagram. Приложение использует Next.js, TypeScript и Tailwind CSS. Supabase отвечает за вход и хранение командных данных, а OpenNext собирает приложение для Cloudflare Workers.

## Что работает в первом релизе

- Поиск по восьми демонстрационным карточкам с фильтрами по платформе, ключевым словам, хэштегам, датам публикации, просмотрам и лайкам. Фильтры применяются до сортировки и ограничения числа результатов. Все введённые ключевые слова и хэштеги должны совпасть.
- Плитка и таблица с сортировкой по дате, просмотрам и лайкам. В карточке можно открыть описание, дату, метрики и хэштеги.
- Личное избранное и коллекции. Коллекция может быть личной или доступной всей команде. Участники могут добавлять видео в доступные коллекции и удалять видео из них.
- В командном режиме Supabase сохраняет избранное, коллекции и журнал запусков демонстрационного поиска. Кнопка «Обновить» загружает изменения коллег.
- Карточка поддерживает официальный плеер TikTok и встраивание публичных публикаций Instagram. У демонстрационных записей нет ссылок на публикации, поэтому они показывают иллюстрации из фотостока. [TikTok Embed Player](https://developers.tiktok.com/doc/embed-player/) · [Instagram Embeds](https://help.instagram.com/620154495870484)

## Запуск в облачной среде разработки

Откройте репозиторий в облачной среде с Node.js 22.12 или новее. Выполните команды и откройте предпросмотр порта 3000.

```sh
npm ci
npm run dev
```

При пустых `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY` открывается деморежим. Избранное и коллекции сохраняются в браузере, и другие пользователи их не увидят. Укажите обе переменные, чтобы включить вход и командное хранение.

## Командный режим Supabase

1. Создайте проект на бесплатном тарифе. В настройках Supabase Auth включите вход по почте и паролю и отключите самостоятельную регистрацию.
2. Выполните команды ниже с помощью Supabase CLI. Обе миграции можно также применить по порядку в SQL Editor проекта. Первая создаёт таблицы и политики RLS, вторая загружает фиксированные демонстрационные записи.
3. В **Authentication → Users** создайте учётные записи команды и подтвердите их адреса. Для каждой записи добавьте профиль с ролью через SQL Editor. Запрос ниже использует существующий UUID пользователя из **Authentication → Users**.
4. Скопируйте `.env.example` в `.env.local` и заполните URL проекта и ключ **Publishable** из настроек проекта. Вход и запросы к данным выполняются на сервере с сессией пользователя. Ключи **Secret** и **service_role** для приложения не нужны.

```sh
npx supabase login
npx supabase link --project-ref YOUR_PROJECT_REF
npx supabase db push
cp .env.example .env.local
```

```sql
insert into public.profiles (id, display_name, role)
values ('00000000-0000-0000-0000-000000000000', 'Имя участника', 'admin');
```

| Роль | Права |
| --- | --- |
| `admin` | Поиск, личное избранное, редактирование содержимого доступных коллекций, создание коллекций и удаление своих или командных коллекций |
| `member` | Поиск, личное избранное, редактирование содержимого доступных коллекций, создание и удаление собственных коллекций |
| `viewer` | Поиск, чтение доступных коллекций и личное избранное |

Личные коллекции доступны владельцу. Избранное и журнал поиска видит только владелец. Для отключения доступа администратор базы устанавливает профилю `active = false`. Деактивация сохраняет коллекции этого пользователя. Роли и доступ назначаются в базе через SQL Editor.

## Cloudflare Workers

Проверить сборку и запустить локальный Workers-предпросмотр можно без аккаунта Cloudflare. Для проверки с Supabase скопируйте `.dev.vars.example` в `.dev.vars` и укажите те же переменные. URL для предпросмотра Workers выводит Wrangler.

```sh
npm run check
npm run cf:build
npm run cf:preview
```

Для публикации создайте Worker на тарифе Workers Free. Используйте имя приложения из `wrangler.jsonc` или измените его и одноимённую привязку `WORKER_SELF_REFERENCE`. Задайте обе переменные Supabase в настройках Worker как runtime variables. Для Git-интеграции используйте `npm run cf:build` как команду сборки и `npm run cf:deploy -- --keep-vars` как команду публикации. При ручной публикации выполните эти команды после настройки Worker и входа в Wrangler. Конфигурация не требует платных дополнений, хранилища файлов или отдельного фонового процесса. [Next.js on Cloudflare Workers](https://developers.cloudflare.com/workers/framework-guides/web-apps/nextjs/)

### Подключение существующего Worker к Supabase

Когда база и профили команды готовы, откройте **Workers & Pages → video-research-platform → Settings → Variables and Secrets**. Подготовьте обе переменные в одном обновлении Worker.

| Переменная | Значение |
| --- | --- |
| `SUPABASE_URL` | URL проекта Supabase из диалога **Connect** |
| `SUPABASE_PUBLISHABLE_KEY` | Ключ **Publishable** (`sb_publishable_…`) или прежний **anon** из **Project Settings → API Keys** |

В Cloudflare значения можно хранить с типом **Secret**. Активация версии с обеими переменными включит вход на сайте. Ключи **Secret** и **service_role** Supabase приложение отклоняет. При следующих публикациях через CLI передавайте `npm run cf:deploy -- --keep-vars`, чтобы сохранить переменные из панели. [Переменные Worker](https://developers.cloudflare.com/workers/configuration/environment-variables/)

### Тесты командного режима

Потребуются Docker Compose и Chromium. Тесты запускают временные PostgreSQL, Supabase Auth, PostgREST и локальный Cloudflare Worker. Они применяют миграции, создают тестовые аккаунты и удаляют временный стек по завершении.

```sh
npm ci
npx playwright install --with-deps chromium
npm run cf:build
npm run test:e2e
```

Для запуска с уже установленным Chromium задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Тесты проверяют вход и выход, доступ по ролям, сохранение личного избранного в новой сессии и работу с общими коллекциями.

## Реальные источники данных

Поиск по TikTok или Instagram через их API в этом релизе отсутствует. Серверный интерфейс `VideoProvider` в `lib/providers/index.ts` разделяет провайдеры по платформам. Для каждой интеграции понадобятся официально одобренный API-доступ, проверка доступных фильтров, метрик и квот, а также тестирование с реальными ответами. Будущие ключи провайдеров следует хранить в секретах Worker и использовать только на сервере. Приложение не собирает данные через скрейпинг и не хранит оригинальные видеофайлы.
