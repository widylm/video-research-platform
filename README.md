# Кадр

Русскоязычное рабочее пространство для команды из 2–5 человек, которая исследует короткие видео TikTok и Instagram. Приложение использует Next.js, TypeScript и Tailwind CSS. Supabase отвечает за вход и хранение командных данных, а OpenNext собирает приложение для Cloudflare Workers.

## Что работает

- Поиск по сохранённым видео в командном каталоге и по восьми карточкам в деморежиме. Доступны фильтры по платформе, словам, хэштегам, датам, просмотрам и лайкам. При заданном пороге или периоде неизвестные значения исключаются из результатов.
- Плитка и таблица с сортировкой по дате, просмотрам и лайкам. В карточке можно открыть описание, дату, метрики и хэштеги.
- Личное избранное и коллекции. Коллекция может быть личной или доступной всей команде. Участники могут добавлять видео в доступные коллекции и удалять видео из них.
- В командном режиме Supabase сохраняет видеокаталог, избранное, коллекции и личный журнал поиска. Кнопка «Обновить» загружает изменения коллег.
- Администраторы и участники могут сохранить ролик по ссылке и сразу добавить его в доступную коллекцию. Повторное добавление использует существующую карточку и оставляет её метаданные прежними. Дата, просмотры и лайки заполняются вручную. Пустые значения показываются как «Нет данных».
- Карточка поддерживает официальный плеер TikTok и встраивание публичных публикаций Instagram. У демонстрационных записей нет ссылок на публикации, поэтому они показывают иллюстрации из фотостока. [TikTok Embed Player](https://developers.tiktok.com/doc/embed-player/) · [Instagram Embeds](https://help.instagram.com/620154495870484)

## Запуск в облачной среде разработки

Откройте репозиторий в облачной среде с Node.js 22.12 или новее. Выполните команды и откройте предпросмотр порта 3000.

```sh
npm ci
npm run dev
```

При пустых `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY` открывается деморежим. Избранное и коллекции сохраняются в браузере, и другие пользователи их не увидят. Укажите обе переменные, чтобы включить вход и командное хранение.

## Командный режим Supabase

1. Создайте проект на бесплатном тарифе. В настройках Supabase Auth включите вход по почте и паролю и отключите самостоятельную регистрацию.
2. Выполните команды ниже с помощью Supabase CLI. Для нового проекта SQL-файлы можно также применить в SQL Editor по порядку. Первая миграция создаёт таблицы и политики RLS, вторая загружает восемь демонстрационных записей, третья добавляет командный каталог, четвёртая разрешает редакторам менять название, описание и автора Instagram, пятая добавляет закрытое хранилище обложек.
3. В **Authentication → Users** создайте учётные записи команды и подтвердите их адреса. Для каждой записи добавьте профиль с ролью через SQL Editor. Запрос ниже использует существующий UUID пользователя из **Authentication → Users**.
4. Скопируйте `.env.example` в `.env.local` и заполните URL проекта и ключ **Publishable** из настроек проекта. Вход и запросы к данным выполняются на сервере с сессией пользователя. Ключи **Secret** и **service_role** для приложения не нужны.

```sh
npx supabase login
npx supabase link --project-ref YOUR_PROJECT_REF
npx supabase db push
cp .env.example .env.local
```

```sql
insert into public.profiles (id, display_name, role)
values ('00000000-0000-0000-0000-000000000000', 'Имя участника', 'admin');
```

| Роль | Права |
| --- | --- |
| `admin` | Добавление видео и смена обложек, поиск, личное избранное, редактирование содержимого доступных коллекций, создание коллекций и удаление своих или командных коллекций |
| `member` | Добавление видео и смена обложек, поиск, личное избранное, редактирование содержимого доступных коллекций, создание и удаление собственных коллекций |
| `viewer` | Поиск, чтение доступных коллекций и личное избранное |

Личные коллекции доступны владельцу. Избранное и журнал поиска видит только владелец. Для отключения доступа администратор базы устанавливает профилю `active = false`. Деактивация сохраняет коллекции этого пользователя. Роли и доступ назначаются в базе через SQL Editor.

### Обновление существующего проекта Supabase

Если в проекте уже работает редактирование карточек, примените [`20261119141541_manual_video_covers.sql`](supabase/migrations/20261119141541_manual_video_covers.sql). В более ранней версии последовательно примените недостающие миграции [командного каталога](supabase/migrations/20261119000100_saved_public_videos.sql) и [редактирования карточек](supabase/migrations/20261119000200_edit_video_metadata.sql) перед миграцией обложек. Миграция создаёт закрытый бакет `video-covers`, четыре политики Storage и функцию чтения версий обложек. Существующие данные и настройки API сохраняются.

Каждый новый файл выполняйте целиком через SQL Editor. Миграции выполняются транзакционно с ожиданием блокировки до пяти секунд. Миграция редактирования сохраняет видео, идентификаторы и связи с коллекциями. После применения проверьте, что запрос возвращает восемь демозаписей и равные им счётчики дат и метрик.

```sql
select count(*) as demo_videos, count(published_at) as dates,
       count(views) as view_counts, count(likes) as like_counts
from public.videos where is_mock;
```

После обновления Worker проверьте загрузку, замену и удаление обложки под `admin` или `member`. Под `viewer` откройте общую коллекцию и убедитесь, что обложка видна, а кнопок редактирования нет. Для Storage используются действующие переменные Supabase и сессия пользователя.

## Cloudflare Workers

Проверить сборку и запустить локальный Workers-предпросмотр можно без аккаунта Cloudflare. Для проверки с Supabase скопируйте `.dev.vars.example` в `.dev.vars` и укажите те же переменные. URL для предпросмотра Workers выводит Wrangler.

```sh
npm run check
npm run cf:build
npm run cf:preview
```

Для публикации создайте Worker на тарифе Workers Free. Используйте имя приложения из `wrangler.jsonc` или измените его и одноимённую привязку `WORKER_SELF_REFERENCE`. Задайте обе переменные Supabase в настройках Worker как runtime variables. Для Git-интеграции используйте `npm run cf:build` как команду сборки и `npm run cf:deploy -- --keep-vars` как команду публикации. При ручной публикации выполните эти команды после настройки Worker и входа в Wrangler. Конфигурация не требует платных дополнений, хранилища Cloudflare или отдельного фонового процесса. [Next.js on Cloudflare Workers](https://developers.cloudflare.com/workers/framework-guides/web-apps/nextjs/)

### Подключение существующего Worker к Supabase

Когда база и профили команды готовы, откройте **Workers & Pages → video-research-platform → Settings → Variables and Secrets**. Подготовьте обе переменные в одном обновлении Worker.

| Переменная | Значение |
| --- | --- |
| `SUPABASE_URL` | URL проекта Supabase из диалога **Connect** |
| `SUPABASE_PUBLISHABLE_KEY` | Ключ **Publishable** (`sb_publishable_…`) или прежний **anon** из **Project Settings → API Keys** |

В Cloudflare значения можно хранить с типом **Secret**. Активация версии с обеими переменными включит вход на сайте. Ключи **Secret** и **service_role** Supabase приложение отклоняет. При следующих публикациях через CLI передавайте `npm run cf:deploy -- --keep-vars`, чтобы сохранить переменные из панели. [Переменные Worker](https://developers.cloudflare.com/workers/configuration/environment-variables/)

### Тесты командного режима

Потребуются Docker Compose и Chromium. Тесты запускают временные PostgreSQL, Supabase Auth, PostgREST, Supabase Storage и локальный Cloudflare Worker. Они применяют миграции, создают тестовые аккаунты и удаляют временный стек по завершении.

```sh
npm ci
npx playwright install --with-deps chromium
npm run cf:build
npm run test:e2e
```

Для запуска с уже установленным Chromium задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Тесты проверяют вход и выход, доступ по ролям, сохранение избранного, работу с коллекциями, проверку ссылок, повторное сохранение одного ролика, доступ к обложкам через RLS и ограничения загрузки.

## Реальные источники данных

Поиск работает по каталогу «Кадра». Описание, дата, хэштеги, просмотры и лайки в добавленных карточках вводятся командой. Оригиналы остаются на платформах, воспроизведение работает через их плееры. В плитке кнопка «Предпросмотр» открывает управляемый плеер в самой карточке. Нажатие на название или обложку открывает карточку с деталями. `admin` и `member` могут отредактировать название и описание сохранённых роликов, а для Instagram также указать имя автора.

Ручная обложка имеет приоритет. Если её нет или изображение не загрузилось, карточка TikTok использует `thumbnail_url` с доверенного CDN из официального oEmbed. Такая ссылка может истечь. Для произвольных Instagram-публикаций сейчас нужна ручная обложка. Instagram oEmbed даёт код плеера, а Instagram Media API может выдать отдельную миниатюру при наличии доступа к публикации. Если подходящего изображения нет, карточка показывает текст. Оба плеера загружаются по запросу пользователя. [TikTok oEmbed](https://developers.tiktok.com/docs/en/embed-videos) · [Instagram oEmbed](https://developers.facebook.com/docs/graph-api/reference/instagram-oembed/) · [Instagram Media](https://developers.facebook.com/docs/instagram-platform/reference/instagram-media/v21.0/)

### Ручные обложки

Откройте детали карточки и выберите **Добавить обложку**. Поддерживаются JPEG, PNG и WebP до 5 МиБ. Браузер сохраняет неподвижный JPEG без исходных метаданных, с длинной стороной до 1280 пикселей. Сервер проверяет размер и заголовки JPEG, а бакет принимает до 512 КиБ на файл. Новая обложка заменяет предыдущую. Активные участники команды читают обложки, а администраторы и участники могут добавлять, заменять и удалять их. Демонстрационные карточки сохраняют свои изображения.

На Supabase Free включены 1 ГБ файлового хранилища, максимальный размер загрузки 50 МБ на файл и по 5 ГБ исходящего трафика в месяц для запросов с попаданием в кэш и без. Эти квоты расходуются вместе с остальными данными проекта. Обложки хранятся по одной на ролик и подготавливаются в браузере. Supabase Image Transformations и новый ключ не нужны. [Supabase Pricing](https://supabase.com/pricing) · [Квоты исходящего трафика](https://supabase.com/docs/guides/platform/manage-your-usage/egress) · [Права Supabase Storage](https://supabase.com/docs/guides/storage/security/access-control)

Короткие ссылки раскрываются по HTTP-переходам в пределах официальных доменов. Если площадка раскрывает ссылку только в приложении или на странице, скопируйте оттуда полный адрес публикации. Для проверки доступности можно воспользоваться кнопкой в карточке или открыть оригинал.
